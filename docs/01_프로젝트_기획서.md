## 1. 추진 배경과 현안

제출자는 매월 원자재와 제품의 재고현황을 분석하고, 증감 원인을 찾아 관리대상을 선정하는 업무 흐름을 정리해 제출했습니다. 제출 원문에 적힌 분석 항목은 다음과 같습니다.

- 원자재: 대분류별 재고수량·재고금액 산출, 전월 대비 수량·금액 증감과 증감률 비교, 주요 증감 품목의 원인 분석(입고량 증가, 생산 사용량 변동, 발주량 변동, 생산계획 변경, 과잉·장기재고 발생 여부), Aging 분석, 단가매칭, 관리대상 선정과 개선방안 수립
- 제품: 고객사별 현재고의 전월 대비 수량·금액 증감, 재고 적정성(적정·과잉·불용) 구분, Aging 분석, 장기 미판매·저회전 제품 분류, 단가매칭, 장기·과잉·불용재고 대상 선정, 향후 판매계획 확인, 재고 소진·감축방안 수립

원문에서 특히 강조된 기준은 **Aging을 입고일 기준과 최근 출고일 기준으로 모두 확인한 뒤, 표시는 최근 출고일 기준으로 한다**는 점입니다. 원자재·제품 두 곳에 같은 기준이 반복 기재되어 있습니다.

현안(가정): 위 항목은 매월 반복되는 작업이며, 두 달치 재고 자료를 맞대어 증감을 계산하고, 입출고 이력에서 날짜를 찾아 Aging을 매기고, 단가를 품목에 붙이는 과정이 엑셀 수작업으로 이루어지고 있을 가능성이 큽니다. 현재 소요시간·사용 시스템은 원문에 없으므로 10절에서 확인합니다.

## 2. 목표

**최종 목표**
월말 재고 자료와 입출고·단가 자료를 넣으면, 원자재·제품 재고 분석표(증감, Aging, 적정성 구분, 관리대상 목록)와 원인 분석 초안이 한 번에 나오는 월간 재고 분석 도구를 만듭니다.

**1차 개발 목표**
- 당월·전월 재고 파일 2개를 올리면 대분류별(원자재)·고객사별(제품) 수량·금액 증감표와 증감률이 자동 계산됩니다.
- 입출고 이력이 있으면 입고일 기준·최근 출고일 기준 Aging을 둘 다 계산하고, 화면 표시는 최근 출고일 기준으로 합니다.
- 단가표를 품번으로 매칭해 재고금액을 산출하고, 매칭 실패 품목을 따로 보여 줍니다.
- 증감 상위 품목과 장기 미출고 품목을 관리대상 후보로 뽑아 엑셀로 내려받습니다.

## 4. 해결 방안 개요

```mermaid
flowchart LR
  A[당월·전월 재고<br/>입출고 이력<br/>단가표] --> B[정리<br/>품번 기준 결합<br/>단가매칭]
  B --> C[분석<br/>증감·증감률<br/>Aging 두 기준<br/>적정·과잉·불용]
  C --> D[관리대상 선정<br/>증감 상위·장기재고]
  D --> E[AI 원인 설명 초안<br/>입고·사용·발주·계획 변동]
  E --> F[산출물<br/>분석표 엑셀<br/>월간 보고 초안]
```

1. **수집**: 월말 재고 파일과 입출고·단가 파일을 그대로 올립니다. 컬럼 이름이 달라도 첫 사용 때 한 번 짝지어 두면 다음 달부터 그대로 씁니다.
2. **정리**: 품번을 기준으로 당월·전월 재고, 입출고 이력, 단가를 한 표로 합칩니다. 단가가 없는 품목은 매칭 실패 목록으로 분리합니다.
3. **분석·AI**: 증감·증감률, Aging 구간, 적정·과잉·불용 구분을 계산합니다. 증감 상위 품목에 대해서는 입고량·사용량 변화를 나란히 보여 주고, 원인 문장 초안은 생성형 AI가 씁니다(담당자 확인 전제).
4. **산출물**: 원자재·제품 분석표와 관리대상 목록을 엑셀로 내려받고, 월간 보고 초안 문장을 복사해 씁니다.

## 8. 개발 단계

**1단계 — 지금 바로 개발 가능한 부분**
실제 파일은 아직 받지 못했지만, 원문에 분석 항목과 Aging 기준이 명확하므로 다음은 바로 만들 수 있습니다.
- 컬럼 짝짓기 방식의 업로드 화면(실제 컬럼명을 몰라도 동작)
- 당월·전월 재고 비교(대분류별·고객사별 증감, 증감률)
- 단가매칭과 매칭 실패 목록
- Aging 두 기준 계산과 출고일 기준 표시, 적정·과잉·불용 구분(구간 기준값 입력식)
- 관리대상 후보 목록과 엑셀 내려받기
- 검증은 형식을 흉내 낸 가상 샘플 데이터로 합니다(가정). 실제 샘플을 받으면 즉시 교체합니다.

**2단계**
- 제출자에게 받은 익명화 샘플로 컬럼·계산 결과를 대조하고, 기존 엑셀 분석 결과와 숫자가 같은지 확인
- 입고량·사용량·발주량 전월 비교를 붙여 증감 원인 보조 화면 구성
- 제품 장기 미판매·저회전 기준 확정

**3단계**
- 관리대상 원인·개선방안 AI 초안(익명화 후 전송)
- 여러 달 누적 추이, 판매계획 반영
- Make로 월간 보고 자동화

## 9. 기대 효과

- 매월 반복되는 두 달치 대조·증감 계산·단가 매칭을 파일 업로드 한 번으로 줄입니다.
- Aging 기준(최근 출고일 기준 표시)을 도구에 고정해 담당자가 바뀌어도 같은 기준으로 분석됩니다.
- 관리대상 선정이 일정한 규칙으로 뽑혀, 과잉·장기·불용재고를 놓칠 가능성이 줄어듭니다.
- 원인 분석과 조치 수립에 쓰는 시간을 늘릴 수 있습니다.

(원문에 수치 목표가 없어 정량 효과는 적지 않았습니다.)

9. 관리대상 선정 기준(증감 상위 몇 건, 금액 기준 등)

### 11.1 요청 원문

> 1. aging분석의 기준을 "일"이 아닌 "월"단위 요청드립니다.
> 2. 원자재 분석관련해서는 대분류를 기준으로 전월대비 증감및 원인파악도 함께 필요합니다.
> 참고사항: 당사 공장은 인천, 대구, 중국공장이 있으며 재고분석 대상은 인천과 대구공장입니다.

(본문 캡처: 1단계 도구의 「Aging · 적정성」 설정 화면 — 90/180/365일 구간을 월 단위로 바꿔 달라는 뜻)

### 11.2 반영 방식

**① Aging 을 「개월」 단위로**

- 구간 경계·과잉·불용 기준을 모두 개월(정수)로 입력·표시·집계합니다. 처음 값은 예전 일 단위 예시 값을 월로 환산한 **3·6·12개월, 과잉 6개월 초과, 불용 12개월 초과**입니다(일 ÷ 30.4375 반올림: 90→3, 180→6, 365→12).
- **월 경과 계산 규칙**(`js/logic.js` `monthsBetween`, 테스트 포함)
  1. 경과 개월 = (기준일의 연×12 + 월) − (날짜의 연×12 + 월)
  2. 기준일의 「일」이 날짜의 「일」보다 작으면 한 달이 덜 찬 것이므로 1을 뺍니다.
  3. 단, 기준일이 그 달의 **말일**이면 빼지 않습니다. 예: 1월 31일 → 2월 28일 = 1개월, 2024-02-29(윤년) → 2025-02-28 = 12개월.
  4. 날짜가 기준일보다 뒤면 계산하지 않습니다. 월말 기준일이면 「같은 달 = 0개월, 지난달 = 1개월」입니다.
- 표시 기준 순서: 최근 출고일 → (출고 이력이 없으면) **재고 파일의 경과 개월 칸**(실데이터의 「재고잔량분석」 「잔량분석」 — 「12 개월초과」는 13개월로 읽음) → (설정 시) 최근 입고일.
- 예전 일 단위 설정을 저장해 둔 사용자는 처음 열 때 자동으로 개월로 바뀌고 알림이 뜹니다.

**② 원자재 대분류 전월 대비 증감과 원인**

- 대분류별 전월·당월 품목 수(종)·수량·금액, 증감, 증감률 — 실데이터 요약표(「원자재」 시트)와 같은 형태입니다.
- **금액 증감 분해**(요인을 모두 더하면 금액 증감과 정확히 같음)
  - 두 달 모두 재고가 있는 품목: 수량 효과 = (당월 수량 − 전월 수량) × 전월 단가, 단가 효과 = 당월 수량 × (당월 단가 − 전월 단가). 단가는 금액 ÷ 수량입니다.
  - 수량 효과는 다시 **입고**(당월 입고 × 전월 단가), **출고·사용**(− 당월 출고 × 전월 단가), **조정·기타**(나머지 — 실사 차이·이동·이력 누락)로 나눕니다.
  - 신규 품목 = 당월 금액, 소멸 품목 = − 전월 금액, 금액을 못 구한 품목 = 금액 미산정.
- 대분류마다 **금액 증감 기여 상위 N 품목**(기본 5)과 가장 큰 요인, 입고·출고 수량의 전월→당월 변화를 보입니다.
- **원인 메모**(담당자 입력, 기준일·공장 보기별 저장)와 **AI 해설 프롬프트**(반자동 — 복사해 ChatGPT 등에 붙여 넣고 답을 다시 붙여 넣음, 품번·품명은 기본으로 가림). 메모·해설은 엑셀 「원자재_증감원인」 시트에 함께 나갑니다. 제품(고객사별)도 같은 화면을 둡니다.
- **두 달 불러오기**: 당월·전월 자리는 원래 있었고, 이번에 (a) 한 통합문서의 7월·8월 시트를 자리별로 자동 선택, (b) 한 시트에 「7월재고수량·8월재고수량」처럼 두 달 칸이 나란히 있으면 자리마다 해당 달 칸을 자동 짝, (c) 제목 줄 날짜로 당월 기준일 자동 입력을 더했습니다.
- **ERP 대분류 코드 → 보고서 대분류 묶음표**(기준 설정): 실데이터 상세 시트의 대분류는 HSG·TML 같은 코드이고 요약표는 하우징류·터미널류입니다. 묶음표 처음 값은 인천 본사 요약표와 같은 숫자가 나오는 짝입니다(11.4).

**③ 공장 구분(인천·대구, 중국 제외)**

- 자리마다 파일을 공장별로 여러 개 올립니다. 파일마다 공장을 지정하고, 파일 이름에 「본사」「인천」「대구」가 있으면 자동으로 골라 둡니다(본사 = 인천 — 가정). 파일에 공장 칸이 있으면 그 값이 먼저입니다.
- 공장 칸에 「중국」이 적힌 행은 분석에서 빼고 몇 행을 뺐는지 알려 줍니다.
- 분석 화면 위 **공장 보기(합계·인천·대구)** 가 모든 화면과 엑셀에 적용됩니다. 합계 보기에는 공장별 요약 표가 붙습니다. 한 공장의 전월 자료가 빠져 있으면 그 공장 품목이 모두 「신규」로 잡힌다고 경고합니다.

**그대로 못 한 것과 대안**

- 발주량·생산계획 변경은 데이터로 계산할 수 없어 원인 메모 칸과 AI 프롬프트의 「확인 필요」 지시로 대신합니다.
- 실데이터에는 입고·출고 이력이 없어, 입·출고 분리는 이력 파일(또는 재고 파일의 당월 입고·출고 칸)이 있을 때만 됩니다. 없으면 수량 효과가 모두 「조정·기타」에 잡히고 화면에 안내합니다.

### 11.4 실데이터 대조 결과 (로컬에서만 확인, 값은 리포에 없음)

- 대구 원자재 7월·8월 상세 시트를 도구로 읽은 대분류별 수량·금액·합계와 증감이 대구 「원자재」 요약표와 원 단위까지 같습니다(요약표는 클립류·스위치를 기타에 포함 — 묶음표에서 두 줄을 빼면 같음).
- 인천 원자재 8월 상세 시트의 대분류별 수량·금액이 인천 요약표와 같습니다. 단 요약표의 「파크라케이블(CI184)」 줄은 품번 기준을 몰라 기타에 들어가 있습니다(11.5-3).
- 도구의 「불용(12개월 초과)」 금액이 두 공장 모두 총괄표의 자재 「불용」과 같고, 제품 8월 금액도 총괄표 제품(정상+불용)과 같습니다. 합계 줄·출력 일시 줄을 빼지 않으면 금액이 두 배로 잡히는 것을 확인하고 자동으로 빼게 했습니다.

### 11.5 남은 확인사항 (실데이터 도착 후 새로 생긴 것 포함)

1. **인천(본사) 7월 원자재 상세 시트** — 이번 파일에는 8월 상세만 있어 인천 원자재는 품목별 전월 비교가 안 됩니다(대구는 7·8월 모두 있음). 7월 파일이나 7월 시트를 받아야 합니다.
2. **대분류 묶음표 확정** — HSG=하우징류, SEAL=씰류, TML=터미널류, TUBE=튜브류, WIRE=와이어류, CLIP=클립류, SWITCH=스위치, 그 밖(FUSE·GROMMET·LOCK/HOLDER·DIODE·CRTUBE·DUMMY SEAL·TAPE·빈칸 등)=기타가 맞는지. 대구 요약표는 클립류·스위치를 기타에 넣는데 두 공장을 통일할지.
3. **「파크라케이블(CI184)」 대분류에 들어가는 품목 기준** — CI184 품번 전부를 넣으면 요약표보다 많습니다.
4. **재고잔량분석(경과 개월)의 기준** — 입고일 기준인지 최근 출고일 기준인지. 원래 요청은 「출고일 기준 표시」입니다. 「12 개월초과」 위를 더 나눌 필요가 있는지.
5. **입고·출고(사용) 수량 자료** — ERP 에서 월 입출고 내역을 내려받을 수 있는지. 있으면 증감 원인이 입고·출고로 나뉩니다.
6. **과잉 구간** — 회사 총괄은 정상/불용 2단계입니다. 도구의 「과잉(6개월 초과~12개월)」을 쓸지, 기준을 몇 개월로 둘지.
7. **반제품** — 파일에 반제품 시트·총괄 항목이 있으나 이번 도구 범위(원자재·제품) 밖입니다. 필요한지.
8. **본사 = 인천공장**이 맞는지(파일 이름 기준 가정), 요약표 기준 명칭(법인명)과 공장의 대응.
9. **종수 세는 방식** — 대구 7월 하우징류 요약표 종수와 상세 시트 품번 수가 2개 다릅니다(재고 0 품목 포함 여부 등).
10. **고객사 이름 표기** — 파일마다 ㈜/(주), 옛 이름·새 이름이 섞여 있어 고객사별 합계가 갈립니다. 묶음 규칙이 필요한지.
