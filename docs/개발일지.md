# 개발일지 — 2026-09-30 (11차) · 이동평균법 단가 계산 · 단가 기준 비교

수강생 요청 「단가 계산이 선입선출 역산으로 되어 있는데 이동평균법으로 바꾸는 것을 추진 중이라, 이동평균법 계산도 할 수 있게」를 반영했습니다(기획서 11.18·11.19, v0.8). 지금 방식(현행)을 처음 값으로 그대로 두고, 이동평균법과 선입선출 역산을 품목마다 따로 계산해 나란히 보이게 했습니다. 실데이터는 이번 요청에 없어 가상 데이터로만 확인했습니다.

## 한 일

- **구매현황 입고 단가 보존** — `receiptIndex().byCode` 를 `[입고일, 수량, 단가]` 로(예전엔 단가를 버림). `fifoCover` 층에 `price`. 저장된 구매현황 파일에는 단가가 이미 들어 있어 다시 올릴 필요 없음.
- **`fifoValue(fifo, 파일 단가)`** — 선입선출 역산 금액 = 층마다 덮은 수량 × 그 입고 단가, 이력으로 못 덮은 수량·단가 빈 층은 파일 단가(수량 따로 셈), 입고 단가로 센 수량이 없으면 못 셈.
- **`movingAverage({ receipts, issues, opening, asOf })`** — 날짜 순(같은 날 입고 먼저), 입고마다 (Q·평균 + q·p) ÷ (Q + q), 출고는 Q 만 줄임, 0 아래면 0 으로 맞추고 셈(`clamped`), 단가 빈 입고는 수량만(`noPrice`). 전월 재고가 있으면 전월 기준일의 수량·금액에서, 없으면 첫 입고부터(`start: 'history'`).
- **출고** — 출고 이력(날짜별, `issueMap`) + 판매현황(`salesIssuesOf` — 달 합계를 그 달 말일로, 원자재는 중국공장 거래처 설정을 따름).
- **`analyzeKind`** — 구매현황이 있으면 당월 재고 품목마다 `it.pc`(현행·선입선출·이동평균 단가·금액·차이·비고). 구매현황에 단가 있는 입고가 한 번도 없는 품목은 이동평균 대상에서 뺌(생산품에 전월 단가가 그대로 이어지는 것처럼 보이지 않게). 구분마다 `priceCompare`(대분류·고객사별 + 합계, 못 센 품목은 현행 금액으로 더하고 건수).
- **설정 `amountBasis`** — file(현행, 처음 값) · fifo · mavg. 현행이 아니면 계산한 품목의 당월 금액을 바꾸고 출처 「이동평균」「선입선출 역산(일부 파일 단가)」, 못 세면 「파일 금액 — 이동평균 계산 못 함」. 합계·Aging 금액·보고용 시트·대조·증감 원인이 모두 따라감. 전월 금액은 현행 그대로.
- **화면** — 분석 화면마다 「단가 기준 비교」 상자(방법 설명 · 공장별 · 대분류/고객사별 · 품목별 차이 큰 순), 현행이 아니면 「당월 금액 단가 기준」 줄. 기준 설정에 「단가 기준(당월 재고금액)」.
- **엑셀** — 「단가_비교」 시트(설명 · 공장×구분 합계 · 구분별 · 품목별), 「기준」 시트 한 줄. 시트 23개.
- **`supabase/schema.sql`** — `app_settings.amount_basis`(file·fifo·mavg, 처음 값 file) 1-E 절, 예전 판에도 칸이 더해짐.
- **예시 데이터** — 구매현황 입고 단가를 품목마다 다르게(2025년 90% · 2026년 1~7월 95% · 8월부터 100%), `samples/` 구매현황 5개 다시 만듦.

## 결정과 이유

- **처음 값은 현행** — 회사 보고서와 대조가 지금처럼 맞아야 하고, 이동평균 전환 시점·시작 금액이 아직 정해지지 않았습니다(11.19-1).
- **전월 금액은 현행** — 전월은 이미 확정된 금액입니다. 방법을 바꾼 효과는 증감 원인의 「단가 변동」에 드러납니다.
- **판매현황은 월말 출고로** — 파일에서 달 합계만 읽어 둡니다. 이동평균은 출고가 평균을 바꾸지 않아 영향이 입고 순서에만 있고, 전월 재고에서 시작하면 한 달 안의 일이라 작습니다. 날짜 순이 필요한지 여쭘(11.19-2).

# 개발일지 — 2026-09-30 (저녁) · 구매현황(입고) 여러 파일 · 입고 FIFO Aging · 실데이터 검증 · 제품 6개월 이상 불용

## 한 일

- **구매현황(입고) 여러 파일** — 「자료」에 판매현황과 같은 흐름의 카드(여러 파일·진행률·작업자 스레드·file:// 대체). `scanReceipts`·`readReceiptWorkbook`(19칸 머리행에서 필요한 칸만, 「발주일·납기일자·최종수정일시」가 입고일로 잡히지 않게), 전표 순번, 계·총합계·출력일 줄 제외, 마감 전 파일 표시. `receiptIndex`: 겹친 기간 중복 제거(파일마다 같은 줄 수의 최댓값 — 한 파일 안의 똑같은 줄은 유지), 달별 줄 수·빈 달, 반품 제외, 적요 제외 규칙. 입고 이력 자리가 비면 구매현황을 입고 이력으로.

## 결정과 이유

- **입고 FIFO 를 처음 값으로 하지 않음** — 회사 칸과 5% 안팎만 같아, 처음 값으로 두면 회사 보고서와 Aging 이 크게 달라집니다. 구매현황을 올리면 참고 상자로 늘 보이게 했습니다.

- **답 「6개월 이상」을 처음 값으로** — 인천은 「초과」가 숫자와 맞지만 답을 우선하고 여쭙니다. 설정 하나로 바꿀 수 있습니다.
